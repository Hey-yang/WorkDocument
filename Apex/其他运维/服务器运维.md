# 服务器运维（Docker 磁盘与日志）

> [!tip] 通用前提
> 下方命令按各服务器已确认的目录编写；换到新机器执行时，先用 `docker info` 确认实际存储目录再替换：
> ```bash
> sudo docker info | grep "Docker Root Dir"
> ```

## 一、服务器清单

| 服务器 | Docker 数据目录 | 备注 |
| --- | --- | --- |
| `18.141.126.161` | `/data/docker/data/` | 日志清理脚本按此路径 |
| `10.8.0.32` | `/var/lib/docker` | Azure QA 环境 |

## 二、磁盘占用排查

```bash
# 确认 Docker 占用的空间
docker system df

# 确认 Docker 的存储目录
sudo docker info | grep "Docker Root Dir"

# 检查当前使用的日志驱动
sudo docker info --format '{{.LoggingDriver}}'
```

## 三、清理容器日志

容器日志通常是磁盘被占满的首要原因，`truncate -s 0` 清空文件但不影响运行中的容器。

### 18.141.126.161

```bash
# 查看日志总大小
sudo find /data/docker/data/ -type f -name "*.log" -exec du -ch {} + | grep total

# 清空所有日志
sudo find /data/docker/data/ -type f -name "*.log" -exec truncate -s 0 {} \;
```

### 10.8.0.32（Azure QA）

```bash
# 查询日志占用
sudo find /var/lib/docker -type f -name "*.log" -exec du -ch {} + | grep total

# 删除日志
sudo find /var/lib/docker -type f -name "*.log" -exec truncate -s 0 {} \;
```

### 验证清理结果

```bash
# 应显示 0B total
sudo find /data/docker/data/ -type f -name "*.log" -exec du -ch {} + | grep total
```

## 四、定位日志异常的容器

```bash
# 按日志大小排序，列出最大的 20 个日志文件
sudo find /data/docker/data/ -type f -name "*.log" -exec du -h {} + | sort -rh | head -n 20

# 关联容器 ID 与容器名称（将 <container-id> 替换为实际 ID 前缀）
docker ps --no-trunc | grep $(echo <container-id> | cut -c1-12)
```

定位到具体容器后，再决定是清理日志、重启容器，还是调整其日志配置。

## 五、清理镜像与构建缓存

```bash
# 一键清理所有构建缓存
docker builder prune

# 删除所有未被容器使用的镜像
docker image prune -a
```

> [!caution] `docker image prune -a` 会删除所有未被容器引用的镜像
> 下次启动相关服务时需重新拉取镜像，请确认没有依赖本地构建产物、且未打 tag 保留的镜像。

## 六、标准处理流程

1. `docker system df` — 判断是镜像、容器还是日志占用
2. `docker info | grep "Docker Root Dir"` — 确认目录
3. 查日志总量 → 按大小排序定位异常容器
4. `truncate -s 0` 清空日志 → 复查是否归零
5. 仍不足时清理构建缓存 / 悬空镜像
6. 追查日志暴涨的容器，从源头限制日志大小
